# Historica — ТЗ на событийную аналитику и воронки

**Сайты:** https://www.historica.org/ и https://map.historica.org/  
**Исполнитель:** frontend-разработчик (часть событий требует backend-интеграции)  
**Цель:** измерять путь пользователя от посещения сайта до изучения карты, использования инструментов, отправки обратной связи и пожертвования.

## 1. Базовая интеграция

1. Проверить текущие Google Analytics / Google Tag Manager и выбрать единый инструмент событийной аналитики (GA4, PostHog или аналог). Не дублировать существующий pageview.
2. Настроить сбор событий на обоих поддоменах и согласованную псевдонимную идентификацию пользователя/сессии при переходах между ними с учётом согласия пользователя.
3. Для событий передавать: `event_name`, `timestamp`, `session_id`, `distinct_id`, `page_url`, `source_site` (`website`/`map`), `referrer`, `device_type`. Если SDK заполняет поле автоматически — не дублировать.
4. Использовать единый нейминг `snake_case`, документировать допустимые значения параметров.
5. Не собирать персональные данные и полный текст пользовательского ввода без отдельного согласования; учитывать GDPR и consent management.

## 2. Основной сайт — historica.org

| Событие | Триггер | Параметры |
|---|---|---|
| `page_viewed` | Открыта страница / сменился маршрут | `page_path`, `page_title` |
| `navigation_clicked` | Клик по разделу меню | `section_name`, `destination` |
| `section_viewed` | Блок попал в область видимости | `section_id` |
| `section_engagement` | Завершён интервал активного просмотра блока | `section_id`, `duration_seconds` |
| `map_cta_clicked` | Клик по ссылке/кнопке карты | `button_location`, `destination` |
| `donation_clicked` | Клик Donate | `button_location`, `provider` |
| `payment_started` | Начало оплаты, если поддерживается провайдером | `provider` |
| `donation_completed` | **Подтверждённый платёж** | `amount`, `currency`, `transaction_id` (только неперсональный ID) |

**Измерение времени:** учитывать только активную видимую вкладку, исключать длительное бездействие (предлагаемый порог — 60 секунд). Для блоков использовать `IntersectionObserver` (например, ≥50% видимости). Накопленное время фиксировать при смене блока/маршрута, скрытии вкладки и завершении сессии; не отправлять heartbeat каждую секунду.

**Пожертвования:** событие `donation_completed` должно поступать только после подтверждения провайдером через backend/webhook, с дедупликацией по ID транзакции. Frontend не должен самостоятельно считать клик успешной оплатой. Не отправлять платёжные реквизиты.

## 3. Интерактивная карта — map.historica.org

### 3.1. Годы и временная шкала

| Событие | Триггер | Параметры |
|---|---|---|
| `map_opened` | Карта успешно загружена | `initial_year` |
| `year_selected` | Пользователь закончил выбирать год | `year`, `selection_method` |
| `year_engagement` | Завершено активное изучение выбранного года | `year`, `duration_seconds` |
| `timeline_interaction` | Завершённое действие с таймлайном | `interaction_type` |

- Не отправлять `year_selected` для каждого промежуточного года при перетаскивании слайдера; использовать `pointerup`/`change` или debounce ~500 мс.
- Время изучения года считать после отображения соответствующего состояния карты, исключая скрытую вкладку и бездействие.
- Поддерживать исторические годы до н. э. в согласованном числовом формате (например, отрицательные значения); документировать отсутствие/наличие нулевого года.

### 3.2. Верхняя панель

| Элемент | Событие | Параметры |
|---|---|---|
| Поиск | `search_opened` | — |
| Поиск | `search_submitted` | `query_length`, `query_category`; полный `query` — только после проверки приватности |
| Поиск | `search_result_selected` | `result_type`, `result_id` |
| Скриншот | `screenshot_clicked` | `year`, `map_view` |
| Скриншот | `screenshot_completed` | `year`, `success` |
| Вид карты | `map_view_opened` | — |
| Вид карты | `map_view_selected` | `view_type` |
| Слои | `layers_opened` | — |
| Слои | `layer_toggled` | `layer_id`, `enabled` |
| Обратная связь | `feedback_opened` | — |
| Обратная связь | `feedback_submitted` | `feedback_type`, `success` |

`feedback_submitted` с `success=true` отправлять только после успешного ответа API. Текст обратной связи не включать в стандартные аналитические события; при необходимости хранить отдельно с контролем доступа.

## 4. Воронки для аналитики

Настроить воронки по уникальным посетителям и отдельно по сессиям; определить окно конверсии и правило порядка событий.

1. **Website → Map:** `page_viewed` (website) → `map_cta_clicked` → `map_opened` → `year_selected` → engaged session (например, ≥60 секунд активного времени на карте).
2. **Map Engagement:** `map_opened` → `year_selected` → просмотр ≥2 различных лет → использование ≥1 инструмента (поиск, слои, вид карты, скриншот).
3. **Search:** `search_opened` → `search_submitted` → `search_result_selected`.
4. **Feedback:** `map_opened` → `feedback_opened` → `feedback_submitted` (`success=true`).
5. **Donations:** `page_viewed` (website) → `donation_clicked` → `payment_started` (если доступно) → `donation_completed`.

Учитывать, что посетители могут попадать непосредственно на карту или страницу пожертвований: для них нужны отдельные сегменты, а не искусственное включение в воронку с главной страницы.

## 5. Дашборды и показатели

**Website:** посещения, уникальные посетители, источники, популярные страницы и разделы, активное время, CTR перехода на карту, конверсия в пожертвование, сумма и средний чек.

**Maps:** популярные годы/периоды, медианное активное время на год, число разных лет за сессию, доля вовлечённых сессий, частота использования поиска/слоёв/видов карты/скриншотов, конверсия в отправку feedback.

**Funnels:** количество пользователей на каждом этапе, конверсия и отток, разбивка по устройствам, источникам трафика и датам.

Предусмотреть экспорт событий/агрегатов через API для будущего **Historica Intelligence Hub**.

## 6. Приоритеты

**P0 — первый релиз:** базовый SDK, межподдоменная идентификация, pageviews, навигация, переходы к карте, `map_opened`, `year_selected`, `year_engagement`, события верхней панели, успешный feedback, клики Donate и подтверждённые пожертвования.

**P1 — следующий релиз:** активное время по блокам, результаты поиска, объекты/регионы карты, ошибки, детальная сегментация.

**P2 — позднее:** анализ сложных путей, A/B-тесты, расширенные продуктовые метрики.

## 7. Критерии приёмки

- События P0 видны в аналитической системе с корректными параметрами и без дублей.
- При переходе `www.historica.org` → `map.historica.org` сохраняется согласованная идентификация сессии/посетителя, если это разрешено настройками согласия.
- Перемещение таймлайна не создаёт сотни событий для промежуточных лет.
- Время взаимодействия не растёт при скрытой вкладке и после порога бездействия.
- `feedback_submitted` фиксирует результат отправки, а не только нажатие кнопки.
- `donation_completed` подтверждается сервером, содержит корректную сумму/валюту и не дублируется.
- Проверены desktop/mobile, переходы между поддоменами, обновление страниц и ошибки API.
- Все пять воронок можно построить на тестовых событиях.
- Передана таблица событий, параметров и инструкция по проверке/экспорту данных.
