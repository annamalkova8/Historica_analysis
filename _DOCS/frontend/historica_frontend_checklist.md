# Historica — чек-лист для frontend-разработчика

**Контекст:** мы строим внутренний Analyst Hub (демо: `historica_analyst_hub_demo.html`), который показывает дашборды и воронки по сайту, карте, соцсетям и Map Builder. Подробное ТЗ по событиям: `historica_tracking_spec.md`.

**Как пользоваться:**
- `[x]` — **уже реализовано** (отметьте после проверки в аналитике)
- `[ ]` — **нужно сделать**
- Если пункт реализован частично или иначе — оставьте `[ ]` и напишите комментарий в строке «Комментарий».
- Приоритеты: **P0** — первый релиз, **P1** — следующий, **P2** — позже.

---

## 1. Базовая интеграция (P0)

- [ ] Проверить, что уже подключено (GA / GTM / другое), выбрать единый инструмент событийной аналитики (GA4, PostHog, Mixpanel или аналог). Не дублировать существующий pageview.
- [ ] Сбор событий работает на обоих сайтах: `www.historica.org` и `map.historica.org`.
- [ ] Единая псевдонимная идентификация посетителя/сессии при переходе www → map (только с согласия пользователя).
- [ ] Каждое событие содержит: `event_name`, `timestamp`, `session_id`, `distinct_id`, `page_url`, `source_site` (`website` / `map` / `builder`), `referrer`, `device_type` (если SDK не заполняет сам).
- [ ] Единый нейминг `snake_case`; таблица событий и допустимых значений параметров передана нам.
- [ ] Consent / GDPR: без согласия события не отправляются; персональные данные и полный текст пользовательского ввода не собираются.
- [ ] UTM-параметры (`utm_source`, `utm_medium`, `utm_campaign`) сохраняются на первом визите и прикрепляются к событиям сессии (нужно для воронки «соцсеть → карта»).

## 2. Основной сайт — historica.org

| ✓ | Событие | Триггер | Параметры | Приор. |
|---|---|---|---|---|
| [ ] | `page_viewed` | открыта страница / смена маршрута | `page_path`, `page_title` | P0 |
| [ ] | `navigation_clicked` | клик по меню | `section_name`, `destination` | P0 |
| [ ] | `map_cta_clicked` | клик по кнопке/ссылке на карту | `button_location`, `destination` | P0 |
| [ ] | `donation_clicked` | клик Donate | `button_location`, `provider` | P0 |
| [ ] | `payment_started` | начало оплаты (если доступно у провайдера) | `provider` | P0 |
| [ ] | `donation_completed` | **подтверждённый** платёж (backend/webhook, дедупликация по ID транзакции) | `amount`, `currency`, `transaction_id` | P0 |
| [ ] | `section_viewed` | блок виден ≥50% (IntersectionObserver) | `section_id` | P1 |
| [ ] | `section_engagement` | завершён интервал активного просмотра блока | `section_id`, `duration_seconds` | P1 |

Правила: время считается только при активной видимой вкладке, порог бездействия 60 с, без heartbeat каждую секунду. `donation_completed` — только после подтверждения провайдером, платёжные реквизиты не отправлять.

## 5. Соцсети, рассылка, публикации

Нужно для дашбордов «Social & Newsletter» и «Publicity» и воронки «соцсеть → сайт → карта».

- [ ] Договориться о UTM-схеме: `utm_source` = `facebook` / `linkedin` / `newsletter`; `utm_medium` = `social` / `email`; `utm_campaign` = id поста/выпуска. (Ссылки в постах и рассылках размечаем мы.)
- [ ] `social_post_click` — первый визит с UTM из соцсети (можно вычислять из `page_viewed` + UTM, отдельное событие не обязательно). P0

- [ ] `article_viewed` — просмотр статьи; параметры `article_id`, `author_id` (если есть). P1
- [ ] Клики с статьи на карту отслеживаются как `map_cta_clicked` с `button_location=article`. P1
- [ ] Откуда берутся данные о числе статей и авторов (70+ статей, 45+ авторов) — CMS/БД? Нужен простой счётчик или выгрузка.

## 6. Воронки, которые должны строиться

Каждая — по уникальным посетителям и отдельно по сессиям; нужно уметь разбивать по источнику, устройству, дате.

- [ ] **Website → Map:** `page_viewed` → `map_cta_clicked` → `map_opened` → `year_selected` → вовлечённая сессия (≥60 с активного времени)
- [ ] **Social → Map:** `social_post_click` → `page_viewed` → `map_cta_clicked` → `map_opened` → `year_selected`
- [ ] **Map Builder → published map:** `mapbuilder_signup` → `map_created` → `objects_added` → `map_published`
- [ ] **Donations:** `page_viewed` → `donation_clicked` → `payment_started` → `donation_completed`
- [ ] **Map engagement:** `map_opened` → `year_selected` → ≥2 разных года → ≥1 инструмент (поиск / слои / вид / скриншот)
- [ ] **Search:** `search_opened` → `search_submitted` → `search_result_selected`
- [ ] **Feedback:** `map_opened` → `feedback_opened` → `feedback_submitted` (success)

Прямые заходы на карту или страницу пожертвований — отдельные сегменты, не искусственно «с главной».

## 7. Данные для Analyst Hub

Хаб показывает два режима: **«Right now»** (то, что считается уже сейчас) и **«What we expect»** (воронки и событийные метрики).

«Right now» — что нужно уметь выгрузить уже сейчас:
- [ ] посетители сайта (за период, по неделям, по источникам)
- [ ] посетители карты (за период, по неделям, по источникам)
- [ ] переходы с соцсетей/рассылки на сайт и на карту (по UTM)
- [ ] число пользователей Map Builder и созданных карт

«What we expect» — после внедрения событий:
- [ ] API или регулярный экспорт событий/агрегатов (JSON/CSV) для хаба; предложите формат и способ доступа
- [ ] показатели: CTR сайт → карта, конверсия в донат, сумма и средний чек, популярные годы, медианное время на год, использование инструментов, конверсия в feedback, воронки по этапам
- [ ] инструкция: как проверить события и как получить выгрузку

## 8. Критерии приёмки

- [ ] События P0 видны в аналитике с корректными параметрами, без дублей.
- [ ] Идентификация сохраняется при переходе www → map (при наличии согласия).
- [ ] Перемещение таймлайна не создаёт события на каждый промежуточный год.
- [ ] Время взаимодействия не растёт при скрытой вкладке и после порога бездействия.
- [ ] `feedback_submitted` фиксирует результат API, а не клик.
- [ ] `donation_completed` подтверждён сервером, с суммой/валютой, без дублей.
- [ ] `map_published` подтверждён backend.
- [ ] Проверено: desktop/mobile, переходы между поддоменами, перезагрузка страницы, ошибки API.
- [ ] Все семь воронок из раздела 6 строятся на тестовых событиях.
- [ ] Передана таблица событий и параметров.
